# Project Structure

Date: 2026-06-12

This file explains where things should live. It is intentionally conservative: do not move existing reports or fixtures unless the scripts that reference them are updated in the same commit.

## Top-Level Folders

| Path | Purpose | Notes |
| --- | --- | --- |
| `app/` | Next.js app routes and global app entry. | Product UI only. |
| `components/` | React UI components. | Editor surfaces live under `components/editor/`. |
| `lib/` | Product logic and shared modules. | Import/export, preview, stores, Blockly, Roll20 helpers. |
| `scripts/` | Repeatable local verification and fixture scripts. | Scripts should write outputs into ignored `reports/` or fixture folders. |
| `docs/` | Human-readable project knowledge. | Specs, QA, operations, UX, validation notes. |
| `reports/` | Local generated verification evidence. | Ignored by Git except `reports/README.md`; do not publish generated reports by default. |
| `test-fixtures/` | Workspace-owned copied fixtures. | Ignored by Git; never mutate external source sheet folders. |
| `.tmp/` | Temporary build/extraction output. | Not source of truth. |
| `out/`, `.next/` | Build artifacts. | Generated by Next.js. |
| `public/` | Static assets served by the app. | Only copyright-safe app assets. Real sheet examples are forbidden in public assets. |

## Current Organization Rules

- Put new operating rules in `docs/operations/`.
- Put edit-mode interaction plans in `docs/ux/`.
- Put active execution state in `docs/qa/31_active_todo.md`.
- Put generated verification output in ignored `reports/<pipeline-name>/`.
- Put repeatable commands in `scripts/`.
- Do not create ad-hoc root-level markdown files unless they are entrypoints such as `README.md`.
- Do not publish generated reports without sanitizing sheet names, snippets, screenshots, asset URLs, and private paths.
- Never write into external source corpora; copy needed samples into `test-fixtures/`.
