# Project Structure

Date: 2026-06-12

This file explains where things should live. It is intentionally conservative: do not move existing reports or fixtures unless the scripts that reference them are updated in the same commit.

## Top-Level Folders

| Path | Purpose | Notes |
| --- | --- | --- |
| `app/` | Next.js app routes and global app entry. | Product UI only. |
| `components/` | React UI components. | Editor surfaces live under `components/editor/`. |
| `lib/` | Product logic and shared modules. | Import/export, preview, stores, Blockly, Roll20 helpers. |
| `scripts/` | Repeatable local verification and fixture scripts. | Scripts should write outputs into `reports/` or ignored fixture folders. |
| `docs/` | Human-readable project knowledge. | Specs, QA, operations, UX, validation notes. |
| `reports/` | Generated or semi-generated verification evidence. | Keep generated outputs here; do not cite them as final proof unless the report scope matches the claim. |
| `test-fixtures/` | Workspace-owned copied fixtures. | Safe to write here; never mutate external source sheet folders. |
| `.tmp/` | Temporary build/extraction output. | Not source of truth. |
| `out/`, `.next/` | Build artifacts. | Generated by Next.js. |
| `public/` | Static assets served by the app. | Only user-facing/static app assets. |

## Documentation Layout

| Path | Use For |
| --- | --- |
| `docs/operations/` | Agent operating rules, handoff rules, current workflow contracts. |
| `docs/spec/` | Product and technical specifications. |
| `docs/ux/` | UX plans, DOM/layer editing model, interaction behavior. |
| `docs/qa/` | Active TODO, QA checklists, current work plans. |
| `docs/qa/archive/` | Old QA snapshots that are not current proof. |
| `docs/validation/` | Validation contracts and verification reports that are stable enough to keep as docs. |
| `docs/perf/` | Performance audit notes and profiling plans. |

## Reports Layout

| Path | Use For |
| --- | --- |
| `reports/corpus-static-audit/` | Static corpus inventory and risk classification. |
| `reports/roundtrip-node/` | Node-side import/emit roundtrip diagnostics. |
| `reports/visual-reference-inventory/` | Reference image inventory. |
| `reports/visual-fixture-render/` | Standalone fixture HTML render evidence. |
| `reports/visual-fixture-diff/` | Browser screenshot/pixel-diff diagnostics. |

## Current Organization Rules

- Put new operating rules in `docs/operations/`.
- Put edit-mode interaction plans in `docs/ux/`.
- Put active execution state in `docs/qa/31_active_todo.md`.
- Put generated verification output in `reports/<pipeline-name>/`.
- Put repeatable commands in `scripts/`.
- Do not create ad-hoc root-level markdown files unless they are entrypoints such as `README.md`.
- Do not move existing generated reports without updating the scripts and docs that refer to them.
- Never write into external source corpora; copy needed samples into `test-fixtures/`.
